# 필수 구현 과제

1. 교육 소개 페이지
교육명, 한 줄 소개, 커리큘럼, 대표 이미지 등을 보여주는 랜딩 페이지를 구현해 주세요.
디자인과 구성은 자유롭게 구성하되, 정보 전달이 명확하면 됩니다.
샘플 데이터 또는 히어로스쿨의 교육 콘텐츠를 사용해도 됩니다.
2. 교육 신청 페이지
이름, 이메일, 주소, 연락 가능 날짜를 입력받는 신청 폼을 구현해 주세요.
반응형 레이아웃을 고려해 주세요.
Ajax를 활용한 비동기 처리 또는 페이지 일부 갱신이 가능하면 좋습니다.
3. 신청 관리 기능
제출된 신청 데이터를 저장·조회·수정·삭제할 수 있어야 합니다.
신청 상태를 구분할 수 있으면 좋습니다. 예: 접수 / 확인중 / 완료
Django admin 또는 별도의 관리자 화면을 활용해도 무방합니다.
4. 백엔드 및 API
Django와 PostgreSQL을 사용해 모델을 설계해 주세요.
교육 신청 관련 간단한 GET/POST API를 DRF로 구현해 주세요.
연락 가능 날짜 기준으로 자동 안내 메일을 전송하는 기능이 있으면 좋습니다.

# 구현 현황

요구사항과 현재 코드를 비교한 요약입니다.

## 필수 구현 과제

1. 교육 소개 페이지
공개된 교육 목록은 `/`, 상세는 `/courses/<slug>/`입니다. 상세에는 교육명, 한 줄 소개, 설명, 커리큘럼, 대표 이미지 또는 대체 영역을 보여 줍니다. 목록과 상세에는 모집 상태와 교육 기간도 함께 나옵니다. 샘플은 `seed` 명령의 파이썬 입문, 웹 서비스 기초입니다.

2. 교육 신청 페이지
신청 폼은 별도 주소가 아니라 모집중인 교육의 상세 페이지에 있습니다. 이름, 이메일, 주소, 연락 가능 날짜를 받고, 좁은 화면에서도 한 열로 입력합니다. 신청 버튼은 Ajax로 `POST /api/applications/`를 호출하고, 접수 결과와 입력 오류만 그 자리에 갱신합니다. 모집 예정과 모집 마감 교육에는 폼 대신 안내 문구를 보여 줍니다.

3. 신청 관리 기능
Django admin에서 신청을 저장·조회·수정·삭제합니다. 상태는 접수, 확인중, 완료이고, 선택한 신청의 상태를 바꾸는 동작이 있습니다. 선택한 신청은 CSV로 내보낼 수 있습니다. 별도의 관리자 목록 페이지는 없습니다.

4. 백엔드 및 API
교육, 커리큘럼, 신청 모델은 Django와 PostgreSQL에 있습니다. DRF로 `POST /api/applications/`와 관리자용 `GET` 목록·상세를 제공합니다. 목록은 상태와 이름·이메일로 거르고 한 페이지에 20건입니다. 수정·삭제 API는 없고 admin이 담당합니다. 신청이 저장되면 확인 메일을 보냅니다. 연락 가능 날짜가 오늘이거나 그 전이고 아직 안내하지 않은 신청에는 `send_contact_notices` 명령으로 안내 메일을 보냅니다. 스케줄러는 두지 않았습니다.

## 우대 구현 과제

1. 신청 목록을 보는 관리자 전용 페이지
구현하지 않았습니다. 신청 목록은 Django admin을 사용합니다.

2. Google Spreadsheet API 연동
구현하지 않았습니다. 신청 목록을 파일로 받는 기능은 admin의 CSV 내보내기입니다.

3. AWS 사용 계획 또는 배포 구성
AWS 계획 문서는 없습니다. 앱을 띄우는 `Dockerfile`과 gunicorn 시작 스크립트, 로컬 Postgres용 Compose는 있습니다.
